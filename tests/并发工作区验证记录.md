# 并发工作区与运行资源验证记录

## 当前规则：以独立任务执行为隔离单位

Git 写任务创建或绑定任务专属 worktree；主 agent 与同一任务的子 agent 共用。追问、调整和中断恢复复用原任务工作区，跨会话接续前核实旧执行者及写入进程停止。不同独立任务并发时分别隔离，即使它们位于同一会话；无需额外建立会话隔离机制。任务完成后仍采用 commit、rebase、验证和目标快进更新。

本轮同步入口、角色、协作、恢复、交接和回合并约定，并补充 M-19 的任务续做观察条件。既有工作区共享及 rebase 机制演练用于检查机制回归，不据此声称已验证模型自动选择任务边界。以下记录、摘要和工件保留原样，均代表当时的被测规则。

本轮实际通过技能格式与包内引用检查、34 项维护测试、2 项工作区共享机制演练及 8 项 rebase 回合并机制演练。任务边界与 M-19 续做规则完成静态核对，未额外运行模型行为场景。

## 后续修订：完成后自动回合并

会话隔离与会话内共享规则保留，新增默认本地提交、仓库级串行回合并及合并后检查。工作区完成不再等同于整个任务完成，具体执行与证据见[自动回合并验证记录](自动回合并验证记录.md)。以下各轮快照与日志保持原样，不作为新规则已执行的替代依据。

## 后续修订：隔离边界改为会话

用户当时进一步明确“不同会话强制 worktree，会话内没必要”。当时规则改为：Git 项目每个写入会话必须绑定专属 worktree；同会话主 agent 与子 agent 共用该路径，按文件分工直接修改，不另建子任务 worktree，不重复应用当前目录中已有的改动。共享 Git 操作由主 agent 统一执行，独立验证前暂停受测范围写入。服务环境仍按需共享、隔离或排队。

新增[会话共享机制演练](验证证据/会话级隔离/共享场景.py)，验证同一会话两个进程在同一 worktree 按文件分工后能直接组合运行，且不改变分支或暂存区、不创建子任务 worktree；另一场景验证不同会话修改同名文件不互相覆盖。实际输出与当前技能摘要分别保存为[修订检查](验证证据/会话级隔离/维护检查.json)及[修订技能快照](验证证据/会话级隔离/技能快照.json)。这轮是维护者机制演练与文档核对，未重新运行模型行为场景，不以此前独立子任务工作区的通过替代现行规则验证。

以下为前一版规则及其历史验证结果。其快照与完整工件保持原样；其中“每个子 agent 独立工作区并回交补丁”已被上述规则替代。

## 机制演练与维护检查

[隔离机制演练](验证证据/并发工作区/隔离场景.py)实际执行 5 项，全部通过：

1. Git worktree 不自动带入未提交／未跟踪内容；显式带入后，主工作区、实现工作区和固定审查副本互不覆盖，源目录保持不变。
2. 两个工作区修改同一行时，真实 `cherry-pick` 报冲突；显式解决后结果保留，另一工作区及其 HEAD 不变。
3. Git 拒绝同一分支被另一个 worktree 同时检出，没有使用强制选项。
4. 同一个 SQLite 数据库中，两名并发执行者按命名空间写入和清理，互不删除数据。
5. 两个真实进程通过同一 POSIX 文件锁排队使用可变资源，独占期间切换并核对版本标记，无需启动两个服务。

这些是维护者对机制的实际验证，不是模型自主选择这些机制的行为证据。SQLite 演练不外推为其他数据库的事务隔离保证；版本标记与进程锁演练也不等于验证了真实 HTTP 应用的版本切换。

[维护检查原始输出](验证证据/并发工作区/维护检查.json)记录技能格式、包内引用、34 项维护测试、原始订单夹具 7 项测试以及上述 5 项演练，均通过。独立静态复核 agent `01a18a6b-99d8-79e0-8ce5-84eaaaf7d283` 读取最终固定技能快照，未发现影响实际并发行为的实质矛盾；它未运行测试或审查机制演练代码，不能据此声称运行验收通过。
