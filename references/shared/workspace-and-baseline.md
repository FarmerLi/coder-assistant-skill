# 工作区与输入基线

## 确认任务工作区

Git 写任务开始前创建或绑定任务专属工作区及分支，不在主线或已结束任务分支启动新工作；使用宿主原生管理入口时保留工作区位置，不为查看搬移源码。读取项目接入参数，核实路径与基线，记录交付路径、目标仓库／分支及起始提交；涉及本地同步时另记目标工作区。并行任务使用独立 worktree 或等效隔离，同一工作区只由一个执行方写入；单任务是否独占前台目录沿用项目约定。已有适用于本任务的 worktree 直接复用；追问、调整和中断恢复沿用原工作区。只读任务不要求创建 worktree，非 Git 项目按已有文件交付约定处理。

父任务的集成工作区与各子项写入工作区分别隔离，记录父集成分支、子 PR 目标及最终主线目标；按[父集成分支](../workflows/delivery-and-closeout.md#父issue集成分支与子pr)区分内部整合与主 PR 交付。

存在未合并代码依赖时，按[依赖 PR 开发](../workflows/delivery-and-closeout.md#依赖pr上的分支开发)记录前置 PR、分支及固定提交，建立下游独立工作区；不在前置工作区继续写入，也不把前置差异当成本项新增成果。

主 agent 与子 agent 使用明确的任务路径、基线和修改归属。开发命令指向该绝对路径，子 agent 可在明确分配且独占的工作区内执行已授权的分支、暂存、提交、推送和子 PR 操作；父集成分支由指定集成负责人单写，主线合并仍按交付授权执行。接口与文件归属按[子代理协作](agent-collaboration.md#文件与接口归属)确认。

## 开发与验收环境初始化

新建开发调试或验收环境需要基础数据时，按项目接入参数定位有版本记录的 Seed 脚本、数据文件或专用数据快照。对同一受测代码，开发调试和验收使用同一份 Seed。核对 Seed 与任务代码及数据库迁移的兼容性，沿用项目准备和导入入口，确认实际装载目标及所需场景数据。可从主工作区取用匹配版本的 Seed，任务 worktree 使用自己的连接配置、凭据和可写数据。

数据结构、默认值或业务流程的变化影响 Seed 时，将受影响的 Seed 纳入同一变更。用该变更的代码、迁移和 Seed，按项目入口初始化独立的干净环境，验证 Seed 能成功装载及受影响的场景能按预期运行。验证结果关联实际受测代码和 Seed 版本。

同一任务续做、重复调试或准备重试时，先核实并复用已有环境及数据，保留已写入的调试记录。需要从头验证初始化时，另用干净环境。缺少兼容的 Seed、导入有缺口或任务需要额外场景时，沿项目现有方式只补所需数据。受限时说明缺口及受影响的验收项，继续其余检查。

## 保留输入与已有修改

记录任务来源、工作区路径、基线提交或文件摘要，以及需要带入的未提交修改。worktree 不会自动继承源目录未提交的内容；相关修改通过快照或补丁带入，包含必要的未跟踪文件，核实后再开始。不在源目录自动提交、暂存或清理用户工作；已有内容不计入本次实现差异。

独立文档仓库、忽略配置和必要依赖不会因创建 worktree 自动可用，须核实实际版本及准备方式。代码隔离、运行资源隔离与业务依赖分别判断；人工接手前停止原写入方并核实状态，交还后再恢复。

勘察结论注明所读状态，相关文件变化后复核。独立验证前核实所有待验差异已包含，检查期间保持相关输入稳定。验证必须绑定实际受测代码与配置，包括应用运行的版本；旧版本服务的通过不能证明本次修改通过。

## 交付与恢复

子 agent 返回实际差异、验证所对应的状态和未完成项。主 agent 核对切片边界、接口与整体回归，按[提交、整合与收尾](../workflows/delivery-and-closeout.md)执行适用交付路径，不因工作区测试通过而跳过项目的 PR 或验收门槛。

恢复前检查实际工作区、未提交修改、子任务和命令状态，不假定上次状态仍然有效。工作区回收条件统一见[资源回收](../workflows/delivery-and-closeout.md#资源回收)，按实际交付路径判断，不为仅交补丁或 PR 的任务额外要求本地回合并；不清理他人工作区。
