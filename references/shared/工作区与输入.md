# 工作区与输入

## 确认任务工作区

Git 写任务开始前按项目约定创建或绑定任务专属工作区，核实路径与基线，记录交付路径、目标仓库／分支及起始提交；涉及本地同步时另记目标工作区。并行任务使用独立 worktree 或等效隔离，同一工作区只由一个执行方写入；单任务是否独占前台目录沿用项目约定。已有适用于本任务的 worktree 直接复用；追问、调整和中断恢复沿用原工作区。只读任务不要求创建 worktree，非 Git 项目按已有文件交付约定处理。

主 agent 与子 agent 使用明确的任务路径、基线和修改归属。开发命令指向该绝对路径，子 agent 的暂存、提交、分支与合并操作交由主 agent 统一执行。接口与文件归属按[子代理协作](子代理协作.md#文件与接口归属)确认。

## 保留输入与已有修改

记录任务来源、工作区路径、基线提交或文件摘要，以及需要带入的未提交修改。worktree 不会自动继承源目录未提交的内容；相关修改通过快照或补丁带入，包含必要的未跟踪文件，核实后再开始。不在源目录自动提交、暂存或清理用户工作；已有内容不计入本次实现差异。

独立文档仓库、忽略配置和必要依赖不会因创建 worktree 自动可用，须核实实际版本及准备方式。代码隔离、运行资源隔离与业务依赖分别判断；人工接手前停止原写入方并核实状态，交还后再恢复。

勘察结论注明所读状态，相关文件变化后复核。独立验证前核实所有待验差异已包含，检查期间保持相关输入稳定。验证必须绑定实际受测代码与配置，包括应用运行的版本；旧版本服务的通过不能证明本次修改通过。

## 交付与恢复

子 agent 返回实际差异、验证所对应的状态和未完成项。主 agent 核对切片边界、接口与整体回归，按[提交、整合与收尾](../workflows/回合并.md)执行适用交付路径，不因工作区测试通过而跳过项目的 PR 或验收门槛。

恢复前检查实际工作区、未提交修改、子任务和命令状态，不假定上次状态仍然有效。确认回合并及必要检查完成、结果与证据已保留且相关进程停止后，才按宿主或项目约定回收本任务临时 worktree；不清理他人工作区。
