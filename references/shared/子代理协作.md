# 子代理协作

## 选择边界

委派用于独立阅读、独立验证或可分开的实现。先看子任务需要多少共享上下文、修改哪些状态、能否给出可检查结果，再选择角色。主 agent 保留完整目标、核心编码和整合责任；需求、设计、测试、实现之间紧密依赖的推理留在同一上下文。

使用宿主已有委派能力，不要求安装额外框架或更改全局配置。角色说明限制任务行为；工具权限和文件隔离由宿主实际机制决定，不能把文字中的“只读”描述成已强制执行的权限。无委派能力时主 agent 顺序完成，独立性不足如实披露。

派发前按[工作区与输入](工作区与输入.md)确认本次任务路径、文件归属及实际基线。

默认一层委派；确需继续拆分时由主 agent 明确修改边界。复用仍适用的现有子任务，避免重复派人调查同一问题。独立复核需要新的上下文，不复用刚完成该实现的 agent。

## 委派最小输入

任务说明可以是一段话，至少让执行者知道：

- **目标与完成条件：** 本次负责的行为、验收和明确排除项；沿用有效来源，不让摘要替代原始规则。
- **必要材料：** 目标项目绝对路径、仓库指令、原始需求及相关代码／测试入口，以及适用的技能方法和角色文件。
- **工作区与归属：** 分配的绝对路径、基线提交／快照和带入的未提交修改、应保留的他人工作、负责修改的位置、共享接口及整合负责人。
- **约束与运行：** 架构、复用、兼容和授权边界；已知基线失败、可用测试环境及允许的副作用。
- **预期返回：** 发现或改动位置、实际检查及证据、未完成项和需要主 agent 决定的问题。

首次独立审查使用无实现会话历史的新上下文，传递原始要求、基线差异、当前代码、必要约束及对应的自动检查证据；不提供预期结论、疑似缺陷位置或“已经正确”等暗示。确认候选或修复复核时可提供前轮具体发现及修复差异，要求独立检验，不能要求同意结论。宿主无法隔离上下文时说明限制，不能称为具有全新视角的独立验证。

## 文件与接口归属

明确负责修改的文件，包括测试夹具、配置、依赖锁文件和生成产物。Git 操作由主 agent 统一执行。按可验收行为分配工作，不按前端、后端、测试等目录机械切断同一行为的反馈循环。

接口相关的切片先对齐契约，在任务工作区中实施，再由主 agent 复核整体。不能独立验收或频繁依赖中间状态的切片合并处理。

预计文件清单不是禁止必要关联修改的白名单。发现需要修改其他负责人文件时先报告依赖，由主 agent 调整归属、顺序或接口；归属未明确前暂停冲突部分，继续无冲突工作。不覆盖他人修改，也不做整体重置。

## 执行、变化与回收

创建调用返回表示任务已启动，不代表任务已完成。主 agent 通过实际完成状态、结果和工件判断进度，在使用依赖结果或最终交付前等待相关任务结束。

需求、接口或工作区变化时，主 agent 明确通知受影响任务；正在写入旧方案的任务须先停止。确认任务及其写入进程已停止、检查实际差异后，再转交文件归属。中断请求本身不证明后台命令已结束。

未完成、失败和阻塞分别报告。子任务遇到缺口时指出具体依赖和可继续部分，不能擅自改变业务规则、降低验收或扩大授权。消息只协调当前子任务；向用户、其他聊天或外部平台发送消息仍按原有授权。

## 回传与整合

返回紧凑、可追查的结果：

| 内容 | 应有依据 |
|---|---|
| 发现与决定 | 代码／材料位置、适用范围、事实与假设的区分 |
| 改动 | 实际修改位置、对应验收、架构与复用选择；只读任务说明是否产生持久改动 |
| 验证 | 实际命令或操作、环境、输入与实现状态、结果及必要输出位置；区分未执行与通过 |
| 缺口 | 未满足行为、阻塞、遗留问题及需要主 agent 决定的事项 |

提交号、文件摘要或可定位的差异均可说明证据对应的状态，不编造版本号。回传工作区、基线与实际差异；应用验收还应说明受测版本，不能仅记录服务地址。无需复制全部探索过程；保留主 agent 可追查的原始输出。

主 agent 核对结果与实际文件，检查跨切片契约和最终差异。子 agent 的“完成”不能替代整体验收。相关代码在验证后变化，旧结果保留原范围，仅对受影响项重新验证；合并后的接口与集成结果由主 agent 确认。

## 审查收敛

按[代码审查](../workflows/代码审查.md)维护发现、修复与误报处置，并依据当前差异复核。审查强度、候选确认和默认 3 轮后的重新评估由该方法统一约定，不在角色说明中建立另一套门槛。主 agent 负责结论和整合，不用子任务数量、通过票数或结束状态替代整体验收。
