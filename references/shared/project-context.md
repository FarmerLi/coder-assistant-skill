# 项目上下文与恢复

## 复用已有入口

从用户指定项目、仓库指令、现有任务、文档及交接定位当前工作。已有共享配置时按下述约定读取 `.project-context.json`；其他等价入口继续复用，不因没有配置文件而阻塞明确的小任务。

已有信息分别承担职责：配置定位代码、文档、任务和测试入口；有效需求与设计界定行为及约束；执行记录保存进展和证据。以引用关联，避免建立相互竞争的正文。

## 技能与项目的内容归属

按内容的维护对象归属，不因多个项目可能使用就将项目规则搬进通用技能：

| 内容 | 维护位置 |
|---|---|
| 任务接收与拆分、调度与状态、TDD、委派、验证、评审、授权边界、交付与恢复的流程和约束 | 技能；项目通过引用采用，不复制完整流程 |
| 项目技术栈、目录／依赖、编码与测试规范、配置准入、UI实现、组件API及实际命令 | 项目代码仓库的规范入口及所属模块文档，随代码一起评审；分支／提交格式、平台字段、目标分支、检查名、交付模式及运行资源参数作为技能接入配置，不另写状态流和审批步骤 |
| 产品目标、业务规则、领域与公共契约、产品交互和业务验收 | 项目指定的需求／设计权威位置；可与代码分仓，不由技能或组件默认值重定义 |
| 本次任务进展、Issue版本、验证证据及交接 | 项目任务／辅助记录，不能写入通用技能 |
| 可复用空白模板、离线测试夹具、技能自身测试和验证记录 | 技能维护资产，不能误迁入某个业务项目；填写后的项目实例归项目 |

流程正文只在技能维护，工程规范只在代码仓库维护，业务需求与验收只在需求／设计权威位置维护。项目入口只声明采用的模式、具体参数和权威链接；真实工具文档描述实际命令及其限制，不另立政策。具体 Issue 保存范围、状态和证据，不能成为通用流程副本。显式用户决定优先；旧项目流程与已采纳技能冲突时定位并修正重复定义，不形成互相要求对方决定的引用环。

已有项目位置优先沿用。用户要求整理或发现本次维护内容放错位置时，移动权威正文并同步入口、引用及必要的历史定位；不保留规则副本，不把维护技能自身的证据误当作产品记录。泛化项目经验须去除项目专属政策，确认跨项目适用后才进入技能；一般编码任务不因此自动扩展为文档迁移。

## 共享项目上下文

持续开发或与 `project-design` 交接时，优先读取目标项目根目录的英文隐藏文件 `.project-context.json`；查找时包含隐藏文件。新建共享配置使用 [JSON 模板](../../assets/project-context-template.json)，只填当前任务必需入口；单次小任务不要求建配置，也不因缺少设计技能或完整设计包而阻塞。

两个技能共用一份配置，字段与含义一致；未使用字段可省略，未知单值为 `null`，值可用中文。

| 字段 | 含义 |
|---|---|
| `project.name`、`project.repository` | 项目名称／代号与实际仓库地址或项目入口，无代码仓库时可用远端项目 URL |
| `project.path_base` | 本地相对路径基准；配置位于项目根目录时为 `.`，本地其他位置显式指定；纯远端可省略 |
| `documents.formal_root`、`documents.support_root` | 当前需求／模型／架构／故事等正式正文入口（不假定编码规范或组件文档也在此目录），以及来源／决策／验证／附件等辅助材料入口；值为本地路径或实际远端 URL／ID |
| `standards`（可选） | 项目已有的规范入口映射，可分别指向代码仓库规范、组件文档和产品交互；键和值沿项目约定；只负责定位，按任务选条目，不递归读取所有链接；不存在时沿仓库指令，无需补建 |
| `tasks.entry`、`tasks.mapping` | 任务系统项目／父项或本地故事入口，以及已有故事／AC／研发测试任务映射位置；未用任务系统时不强制接入 |
| `prototype.tool`、`prototype.source` | 需要原型时的实际工具与可编辑源路径或 URL／ID；预览与业务交互从设计入口定位，UI实现与组件要求沿`standards`或项目规范入口，不以截图代替源 |
| `handoff.design`、`handoff.development` | 设计侧与开发侧各自当前交接记录的路径或 URL／ID；可以指向同一份已有记录中的不同章节，不要求另建文件 |

本地配置使用 UTF-8 JSON 对象，不加 Markdown 围栏、注释或尾随逗号，保存后用 JSON 解析器回读。字段中的本地相对路径以 `project.path_base` 为基准，其自身相对本地配置所在目录解析；配置位于项目根目录时为 `.`，任务 worktree 中按对应项目根解析，不照搬其他任务的绝对工作区。远端值用实际 URL／ID，纯远端可沿用已授权页面“项目上下文”章节中的同组 JSON，不虚构本地路径。

已有 `项目上下文.md`、`PROJECT_CONTEXT.md`、任务正文或远端配置时先复用，不为命名差异另建竞争来源。需要转换时只迁入必要入口，详细约定保留在所属文档并更新引用。未知扩展字段和另一技能维护的入口保持不变，不整份重建或删减已有配置。

跨仓库链接用于定位权威来源，不是全量联网读取要求。本地已有匹配仓库及内容版本时，按仓库相对路径读取同一文件；没有匹配检出时才沿实际可用入口取得相关正文。恢复或引用证据时核对实际版本，不把链接中的main当作执行时快照。

配置只负责定位；平台字段、预览和设计规范、运行／测试命令、进展及证据从对应文档读取。默认文档目录仅用于本地无约定的项目，已有合理位置直接复用，不预生成目录或空文档；配置不保存凭据或授权开关，地址不代表执行授权。

## 与 project-design 双向交接

- **接收设计：** 沿 `handoff.design` 和现有任务读取本次目标、范围与验收、有效需求／故事及相关模型、架构、原型／设计规范的具体来源和修订、阻塞与下一步。依据[输入与证据](input-and-evidence.md)核对当前请求及实际代码，不把设计完成当作实现授权，不要求补跑五阶段。
- **继续开发：** 本次任务采用Issue作为执行依据时，从已纳入本轮执行的Issue／sub-issue及其验收要求进入，按[执行契约](execution-contract.md#issue用途与执行入口)核对用途和依赖，按需补父目标和业务场景来源；本次未采用Issue时沿有效请求或已有任务及验收恢复，不因同一仓库启用Issues要求补建单。项目明确要求关联Issue时按其约定处理；不因技能切换重建任务或复制正式正文。接收信息不足时仅补足影响当前实现的缺口。
- **返回结果：** 更新 `handoff.development` 所指记录，保存实现位置、验收覆盖、实际测试及其代码状态、未完成项与下一步。需要业务或架构决定时记录来源与影响，交回相关设计入口，不静默修改需求，也不把测试通过当作业务确认。
- **维护入口：** 只更新本次必要配置，保留 `handoff.design` 等另一侧信息；设计侧继续时从开发交接读取证据。两侧入口可以指向已有记录的不同章节，不要求两个技能同时安装，也不要求新建独立文件。

## 何时保存

单次小任务在回复中交付即可。持续开发、需要中断恢复或用户要求保存时，优先更新已有任务或工作记录。没有位置约定时，可在目标项目 `docs/development/开发记录.md` 保存最小状态；有等效位置直接沿用，不为了默认命名迁移文件。

可用[开发交接模板](../../assets/development-handoff-template.md)，只保留当前范围所需内容。状态不得写入技能包；本包 `tests/` 仅存技能维护材料和隔离测试夹具。目标项目的新建说明文件优先沿用项目约定，未约定时用中文名称；本技能包的文件命名见README，不将项目产物规则用于技能维护。

远端是正式来源时，本地只维护必要索引或明确标为草稿，不自动建立长期正文镜像。记录实际路径、链接、修订和同步结果，不保存凭据。写回按实际授权执行，地址本身不授权写入、发送消息或新增评论。

## 恢复顺序

1. 读取用户当前请求和适用仓库指令，确认工作项目。
2. 从已有任务或交接定位相关需求、架构、实现和测试；核查来源有效性，不让旧摘要覆盖新决定。
3. 按[工作区与输入](workspace-and-baseline.md)核实原任务路径、有效基线和文件归属；追问、调整与中断恢复优先复用原工作区。检查已有变化、当前实现及最近测试，区分自己的工作与他人修改，不假定上次工作区仍保持原样。有子任务时查询实际状态及仍运行的命令，不能假定原 agent 或工具会话仍可恢复。
4. 对变化做有边界的影响检查；已执行结果保留原范围，必要项重新验证。检查已有审查发现、修复及误报处置，对照最终代码、检查配置和 CI 实际提交核实证据有效性，不因上次记录“通过”就沿用结论。
5. 恢复适用规范、来源状态和未验证条目，检查当前请求、规则或差异是否使旧证据失效；只回读受影响正文，不凭进度摘要继续写入。
6. 恢复下一条有明确验收或验证条件的切片，沿用原任务和追溯关系，不重建重复任务。

交接至少说明：有效目标及来源、当前改动、已完成／未完成行为、最后实际测试及环境、架构和复用决定、阻塞，以及下一步。按[提交、整合与收尾](../workflows/delivery-and-closeout.md)保留已选交付路径、授权边界、目标与提交；PR 路径记录 PR、验收和合并状态，本地路径记录目标工作区及 rebase 前后提交对应关系，采用Issue时保留唯一定位、用途、验收覆盖和实际状态，内容版本及条目映射按[追溯约定](execution-contract.md#执行依据与追溯)保留；分别记录同步、环境准备和清理进度。恢复时先查询实际结果，避免因 squash／rebase 改变哈希而重复交付。存在子任务时补充角色、目标、修改归属、实际状态、待整合结果和证据适用范围，沿用已有记录即可。恢复信息负责导航，不替代业务规则正文。
