# 项目上下文与恢复

## 复用已有入口

从用户指定项目、仓库指令、现有任务、文档及交接定位当前工作。`项目上下文.md`、`PROJECT_CONTEXT.md`、任务正文或远端页面都可能承载配置，不要求任何一种名称或平台，也不因没有配置文件而阻塞明确的小任务。

已有信息分别承担职责：配置定位代码、文档、任务和测试入口；有效需求与设计界定行为及约束；执行记录保存进展和证据。以引用关联，避免建立相互竞争的正文。

## 何时保存

单次小任务在回复中交付即可。持续开发、需要中断恢复或用户要求保存时，优先更新已有任务或工作记录。没有位置约定时，可在目标项目 `docs/development/开发记录.md` 保存最小状态；有等效位置直接沿用，不为了默认命名迁移文件。

可用[开发交接模板](../../assets/开发交接模板.md)，只保留当前范围所需内容。状态不得写入技能包；本包 `tests/` 仅存技能维护材料和隔离测试夹具。新建说明文件用中文名称，代码与项目规定的名称按实际约定保留。

远端是正式来源时，本地只维护必要索引或明确标为草稿，不自动建立长期正文镜像。记录实际路径、链接、修订和同步结果，不保存凭据。写回按实际授权执行，地址本身不授权写入、发送消息或新增评论。

## 恢复顺序

1. 读取用户当前请求和适用仓库指令，确认工作项目。
2. 从已有任务或交接定位相关需求、架构、实现和测试；核查来源有效性，不让旧摘要覆盖新决定。
3. 按[并发工作区](并发工作区.md)核实本会话及子任务的实际路径、独占状态和基线，检查已有变化、当前实现及最近测试，区分自己的工作与他人修改。不假定上次工作区仍保持原样。有子任务时查询其实际状态，检查写入进程和文件归属；确认旧任务不会继续写入后再转交，不能假定原 agent 或工具会话仍可恢复。
4. 对变化做有边界的影响检查；已执行结果保留原范围，必要项重新验证。检查已有审查发现、修复及误报处置，对照最终代码、检查配置和 CI 实际提交核实证据有效性，不因上次记录“通过”就沿用结论。
5. 恢复下一条有明确验收或验证条件的切片，沿用原任务和追溯关系，不重建重复任务。

交接至少说明：有效目标及来源、当前改动、已完成／未完成行为、最后实际测试及环境、架构和复用决定、阻塞，以及下一步。存在子任务时补充角色、目标、修改归属、实际状态、待整合结果和证据适用范围，沿用已有记录即可。恢复信息负责导航，不替代业务规则正文。
