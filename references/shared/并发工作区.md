# 并发工作区与运行资源

支持多个会话同时修改同一仓库。隔离边界覆盖各会话的主 agent 和所有子 agent，不能仅依靠同一会话内的文件归属约定。

## 会话与子任务工作区

- 开始任何项目写入前，确认当前工作区由本会话独占；宿主已分配独立工作区时直接复用。无法确认独占时，优先使用宿主隔离能力或 Git worktree，为本会话建立独立工作区，不直接在用户当前或其他会话的工作目录中写入。
- 每个实现子 agent 使用自己的独立可写工作区；勘察、独立验证使用指定版本的独立工作区或固定快照，不读取其他执行者持续变化的工作目录。一次固定的只读快照可供多个只读任务使用；上下文隔离不能替代文件状态固定。
- 各工作区使用各自分支或 detached HEAD，不让多个执行者移动同一工作分支。所有读取、修改、测试、构建、格式化和生成命令明确指向分配的绝对路径；派发后核实实际路径和基线，不能只凭创建调用成功就认为隔离成立。
- 无 Git 时可使用宿主隔离或独立副本，并保存可追查基线和差异。无法提供独立工作区时，只在已确认独占期间串行写入；确认不了则暂停写入，继续可做的读取。仅在本会话内顺序执行，不能证明其他会话不会同时修改。

## 固定输入与修改归属

派发时记录工作区、任务归属、基线提交或文件摘要，以及需要包含的未提交修改。worktree 不会自动继承源目录的未提交内容；相关修改通过快照或补丁带入，包含必要的未跟踪文件，核实后再开始。不在源工作区自动提交、暂存或清理用户和其他会话的工作；在独立工作区保存输入快照时标明已有内容，不计入本次实现差异。工作区仍在变化时先取得稳定输入，不能把不同时刻的文件拼成一个基线。

同一工作区同一时段只有一个项目写入负责人。不同工作区可以修改同一文件，但先对齐共享接口，标明可能重叠的改动，由所属主 agent 显式整合；频繁依赖中间状态的切片仍应合并或顺序执行。工作区隔离不扩大任务范围，也不免除[文件与接口归属](子代理协作.md#文件与接口归属)的协调要求。

## 按需使用运行资源

代码独立不等于每个 agent 都要启动完整环境。先查项目已有测试入口、资源约定和副作用，再选择足以证明当前行为的最小环境。

| 实际工作 | 运行方式 |
|---|---|
| 勘察、静态审查 | 读取固定代码状态，无需启动服务 |
| 单元测试、局部构建 | 在自己的工作区执行；有外部写入的缓存或输出按需分开 |
| 数据库测试 | 优先复用可共享的实例，用独立测试库、schema、命名空间或经确认可靠的事务机制隔离写入；不能隔离时排队使用 |
| 应用或接口验证 | 仅为实际需要运行应用的任务启动必要组件；并行服务分配可用端口，不按 agent 数量复制整套环境 |
| 昂贵或无法隔离的集成环境 | 协调独占时段，串行验证，或整合后由主 agent 集中执行 |

跨会话共享可变资源时，沿用项目／宿主可见的锁、预约或分配机制；只有本会话知道的约定不算跨会话协调。无法确认可安全共享时，使用独立资源或暂停依赖该资源的检查，其余开发继续；必需验证保持待执行。

运行验收必须绑定实际受测代码与配置状态。共享基础设施可以复用，但另一会话运行的应用或旧版本服务不能证明本次修改通过；串行复用应用时先切换并核实受测版本。临时文件优先使用执行者独立目录，仅回收本任务拥有且已停止使用的资源。

## 整合、变化与回收

子 agent 返回所属工作区、基线、提交或补丁及验证所对应的状态，不直接写回主工作区或其他会话。所属主 agent 核对实际差异后逐项整合，处理重叠修改，再验证受影响接口与集成；跨会话结果也通过明确整合进入当前工作区，不能静默跟随其他分支变化。只读快照不自行更新，需求或目标版本变化时按[协作约定](子代理协作.md#执行变化与回收)停止受影响工作并重新固定输入。

worktree 仍共享部分 Git 元数据；分支引用、仓库配置及清理操作可能影响其他执行者。只操作本任务拥有的分支与工作区，不整体重置、强制更新共享分支或清理他人 worktree。确认执行者及后台进程停止、结果与证据已保留后，才通过宿主或项目约定回收本任务的临时工作区；不为隔离引入自动推送、发布或额外审批。
