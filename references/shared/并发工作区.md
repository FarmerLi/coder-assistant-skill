# 并发工作区与运行资源

隔离单位是一次独立开发任务执行：每个并发写任务使用专属 worktree，该任务的主 agent 与子 agent 共用，由主 agent 协调文件归属。这样即可支持不同会话同时修改同一仓库，无需额外按会话绑定工作区。

## 任务与子任务工作区

- Git 写任务开始前创建或绑定本任务专属 worktree，核实实际路径、归属和基线；已有适用于本任务的 worktree 直接复用。开发写入发生在任务 worktree，原始主工作区留作回合并目标。
- 一次任务执行包含其主 agent 调度的完整实现与验收，不等于一条消息、一次工具调用或一个子切片。追问、调整和中断恢复复用该任务 worktree；同一会话同时执行多个独立写任务时分别隔离。
- 同一任务的主 agent、实现、勘察与独立验证子 agent 共用任务 worktree，不为子任务另建 worktree。更换会话继续同一任务时，先核实旧执行者及写入进程已停止并接续工作区归属；两个未经统一协调的执行者不能仅因任务同名就同时写同一目录。只读任务不强制创建 worktree。
- 各并发任务使用各自分支或 detached HEAD，不移动其他任务的工作分支。开发命令指向本任务的绝对路径；派发时核实子 agent 使用同一任务路径及有效基线。开始时另记录主仓库目标路径、分支及起始提交；只有完成后的[自动回合并](../workflows/回合并.md)阶段，在串行协调下更新该目标工作区。
- Git worktree 不可用时暂停项目写入，继续可做的读取，不退回原目录或独立克隆来绕过任务 worktree 要求。非 Git 项目使用任务独立副本或宿主隔离，并保存基线和差异；不能隔离则暂停写入，不为本规则强行初始化 Git。

## 固定输入与修改归属

建立任务 worktree 时记录任务来源、路径、归属、基线提交或文件摘要，以及需要带入的未提交修改；沿用已有任务与交接，不要求新建会话登记系统或固定编号。worktree 不会自动继承源目录的未提交内容；相关修改通过快照或补丁带入，包含必要的未跟踪文件，核实后再开始。不在源目录自动提交、暂存或清理用户和其他执行者的工作；保存输入快照时标明已有内容，不计入本次实现差异。源目录仍在变化时先取得稳定输入，不能把不同时刻的文件拼成一个基线。

同一任务的委派沿用工作区实际现状，明确已有修改、负责文件及共享接口。同一文件同一时段只有一个修改负责人；不同文件可以并行修改，共享夹具、锁文件和生成产物同样需要归属。共享 Git 索引与分支操作由任务主 agent 统一执行，子 agent 不自行暂存、提交、切换分支或合并。跨文件行为紧密依赖或频繁同步时，合并切片或顺序执行，按[文件与接口归属](子代理协作.md#文件与接口归属)协调。

勘察可读取任务当前代码，结论注明所读状态，相关文件变化后复核。独立验证前主 agent 暂停受测范围内的写入，核实包含所有待验差异，并在检查期间保持相关输入稳定；不相干的开发可继续。对话上下文独立与受测状态稳定分别核实，不要求为验证者另建 worktree。

## 按需使用运行资源

代码独立不等于每个 agent 都要启动完整环境。先查项目已有测试入口、资源约定和副作用，再选择足以证明当前行为的最小环境。

| 实际工作 | 运行方式 |
|---|---|
| 勘察、静态审查 | 读取本任务代码，审查时保持受审范围稳定，无需启动服务 |
| 单元测试、局部构建 | 在任务 worktree 执行；会冲突的缓存或输出按需分开或串行 |
| 数据库测试 | 优先复用可共享的实例，用独立测试库、schema、命名空间或经确认可靠的事务机制隔离写入；不能隔离时排队使用 |
| 应用或接口验证 | 仅为实际需要运行应用的任务启动必要组件；并行服务分配可用端口，不按 agent 数量复制整套环境 |
| 昂贵或无法隔离的集成环境 | 协调独占时段，串行验证，或整合后由主 agent 集中执行 |

不同任务共享可变资源时，沿用项目／宿主可见的锁、预约或分配机制；只有单个任务知道的约定不算跨任务协调。无法确认可安全共享时，使用独立资源或暂停依赖该资源的检查，其余开发继续；必需验证保持待执行。

运行验收必须绑定实际受测代码与配置状态。共享基础设施可以复用，但其他任务运行的应用或旧版本服务不能证明本次修改通过；串行复用应用时先切换并核实受测版本。临时文件优先使用执行者独立目录，仅回收本任务拥有且已停止使用的资源。

## 整合、变化与回收

子 agent 在任务 worktree 直接修改负责文件，返回实际差异、验证所对应的状态和未完成项，不要求额外交付提交或补丁。主 agent 等待相关写入完成，核对切片边界、接口与整体回归；不把已在当前目录中的改动再应用一遍。任务验收通过后，主 agent 按[自动回合并](../workflows/回合并.md)将本次结果提交、rebase 到最新目标、验证并串行快进更新主仓库，不停留在任务 worktree 交付。需求或目标版本变化时按[协作约定](子代理协作.md#执行变化与回收)停止受影响工作，重新确认归属和有效输入。

worktree 仍共享部分 Git 元数据；分支引用、仓库配置及清理操作可能影响其他执行者。只操作本任务拥有的分支与工作区及已记录的回合并目标，不整体重置、强制更新共享分支或清理他人 worktree。确认回合并及必要检查完成、结果与证据已保留、执行者及后台进程停止后，才通过宿主或项目约定回收本任务的临时工作区；不为隔离引入自动推送、发布或额外审批。
