# 完成后的自动回合并

Git 编码任务默认由主 agent 按“本地提交 → rebase 到最新目标 → 验证 → 目标快进更新”交付，同时更新主仓库目标分支及工作区。使用 Git 提交级整合，不复制文件覆盖主仓库，也不默认创建 merge commit。无需逐次询问是否提交或回合并；用户明确只要补丁、不提交、不合并或项目有明确交付流程时沿用其要求。本地回合并不包含自动推送、远端 PR 合并、部署或发布。

## 开始时定位目标

记录目标仓库、原始工作区绝对路径、目标分支及起始提交。优先沿用用户或项目明确的目标；没有另行指定时，使用启动任务的原始工作区当时所在的本地分支，不猜测固定名为 main 或 master，也不把远端地址当成本地目标。目标处于 detached HEAD 或存在多个有效目标时，先查已有任务与交接；仍无法确定则只暂停回合并，继续不依赖该选择的开发。

入口已是会话专属 worktree 时，从宿主创建来源或已有交接定位原主工作区及目标分支，沿用已记录目标，不能把会话分支自身当作回合并目标。缺少来源时先核实仓库 worktree 信息，仍不能确认则报告具体缺口。

记录会话 worktree、任务起始输入与带入的已有修改。只提交本次任务改动，使用明确文件或选定差异暂存，不把用户已有修改、他人工作、缓存和验证工件顺手提交。本次实现若依赖尚未提交且无法分离的已有修改，说明具体依赖并保留结果，不能代用户提交这些内容。

## 串行整合并更新主工作区

回合并由主 agent 执行，先等待本会话相关子任务与后台写入停止。多个会话合并同一仓库时使用同一仓库级合并锁或宿主等效队列；锁位于各 worktree 共用的 Git 目录，约定名称为 `coder-assistant-merge.lock`。锁覆盖读取最新目标、整合验证、更新目标与合并后检查，不能用会话内标记或 Git 短暂的 index.lock 代替。优先使用能随持有进程退出释放的锁，并在本轮等待预算内排队，不无限重试。

持有锁后：

1. **核实目标与前置状态。** 重新确认目标工作区仍检出记录的目标分支、没有进行中的合并／变基及未提交修改，包括暂存和未跟踪文件；确认会话任务提交及其验证证据有效。目标不干净时保留其状态，不自动 stash、提交或清理用户工作，标明回合并暂未完成。
2. **Rebase 到最新目标。** 读取当前目标提交；先核实已记录的任务结果（含 rebase 后提交）是否已被目标包含，已包含时核实目标状态与所需验证，直接报告已合并。否则确认待重放序列只包含本会话尚未共享的任务提交，在会话 worktree 执行 `git rebase --no-autostash <目标最新提交>`。不重放、改写其他会话或已回合并的提交，不强制回退目标；不能确认提交归属时保留结果并报告具体缺口。
3. **验证 rebase 后候选。** 在会话 worktree 处理有明确依据的 rebase 冲突，保存重放前后提交对应关系，再检查实际差异、接口与受影响回归。无法确定正确解法或检查失败时保留会话结果，目标不动，明确报告未合并。没有变化的有效检查可复用，发生重放或冲突修复后不能直接借用 rebase 前通过。
4. **快进更新目标。** 再次核实目标分支、提交及干净状态，使用普通 Git 安全更新，例如在目标工作区执行 `git merge --ff-only --no-autostash <已验证候选提交>`。目标在检查期间又变化时回到最新目标重新整合并验证，不能强制更新引用、reset 或覆盖文件；持续变化时保留结果并报告暂未合并。
5. **核实完成。** 确认目标分支和工作区实际包含本次结果，在目标状态执行项目要求的合并后检查，记录最终提交、受测状态和结果，再释放锁。合并后检查失败时如实报告“已合并、验证失败”，保留现场并修复，不自动重置可能已被其他会话使用的目标。

任务在 detached 会话 worktree 开发也可使用已保存的候选提交；目标必须是已定位的本地分支与工作区。不能绕过 Git 对其他 worktree、未提交修改或分支状态的保护。

## 完成判断与恢复

默认交付同时要求实现验收和回合并完成。仅 worktree 测试通过、仅生成补丁或仅创建本地提交时，分别报告实际进度，不能称已合并回主仓库。非 Git 项目按已有文件交付约定处理，不强行初始化 Git 或伪造合并结果。

Rebase 完成后、更新目标之前即保存原任务提交与 rebase 后提交的对应关系。恢复时先核实原目标、该对应关系、目标当前 HEAD、是否已有 rebase 进行中及是否已包含重放后的结果，再继续；不能仅因原提交哈希改变而重复交付。调用超时或中断不能直接重复提交、rebase、快进或删除 worktree。记录“未合并／已合并待检查／已合并且检查通过”等实际状态。确认目标包含结果、必要检查通过、证据已保留且执行者停止后，才按宿主约定回收本任务的临时 worktree；受阻时保留它。
