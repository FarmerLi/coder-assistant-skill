# 可选的自动检查执行器

本页仅在选择包内[执行器](../../scripts/run_review_checks.py)时使用；检查类别、范围与判断方法见[自动检查](自动检查.md)。项目已有命令或 CI 足够时直接使用，不必建立配置。执行器只用 Python 标准库，顺序执行已配置命令；不调用模型、修改验收、安装依赖或创建宿主钩子。

Python 是执行器的运行依赖，目标项目可以使用任何技术栈。没有可用 Python 时，直接运行项目原生命令并保存等价证据，不为使用执行器改造项目。

## 配置项目命令

配置仅包含 `inputs` 与 `checks`：

- `inputs`：项目内非空路径数组，包含受审代码、测试、相关规则、配置、依赖锁文件及其他会改变结论的输入。递归记录文件内容摘要、文件与目录的权限及目录存在性，含空目录；文件符号链接还记录链接目标，保留显式选择的链接身份。不要仅列改过的单个实现文件而遗漏接口和测试。执行器不会推断完整依赖，也不会追踪外部服务或环境变化。
- `checks`：非空检查数组。每项的 `id` 是唯一的小写英文标识，`argv` 是参数数组；可设项目内 `cwd`（默认 `.`）、正数 `timeout_seconds`（默认 120）及布尔值 `required`（默认 `true`）。非必需项仅适用于项目允许的建议性检查，失败仍显示警告。

例如，**假定目标项目已使用 pnpm，且已定义 `typecheck` 与 `test:ci` 脚本**，可配置如下。路径、脚本、超时及完整必需项须按实际项目调整；此例不要求其他项目安装 pnpm 或增加同名脚本：

```json
{
  "inputs": ["src", "tests", "package.json", "pnpm-lock.yaml", "tsconfig.json"],
  "checks": [
    {
      "id": "types",
      "argv": ["pnpm", "run", "typecheck"],
      "required": true
    },
    {
      "id": "regression",
      "argv": ["pnpm", "run", "test:ci"],
      "timeout_seconds": 300,
      "required": true
    }
  ]
}
```

同样可将 `argv` 指向项目已有的构建包装器、Go／Rust／.NET 命令或其他入口。已有[配置资产](../../assets/自动检查配置示例.json)专用于包内 Python 订单夹具的回归演练，不是所有项目的默认配置。

命令按数组直接执行，不做 shell 展开；通配符、重定向、管道和环境变量赋值不会自动解释。需要这些能力时优先复用项目任务脚本。命令仍有自身权限和副作用，执行器不是权限隔离机制；依赖准备与自动修复在固定检查输入之前完成。

## 运行与结果

使用实际技能目录和目标项目路径调用：

```sh
python3 /path/to/coder-assistant/scripts/run_review_checks.py \
  --project /path/to/project \
  --config /path/to/project-checks.json \
  --output /path/to/new-review-run
```

`--output` 必须是尚不存在的本轮证据目录，不覆盖历史结果。项目内输出会从输入摘要排除；为容纳输出新建的父目录不计目录元数据，但其中其他文件仍须追踪。执行器先校验整份配置，再逐项运行，记录参数、工作目录、UTC 时间、退出码、持续时间、合并原始日志、检查前后输入摘要和配置摘要，最终写入 `result.json`，并向标准输出返回同一 JSON。继承运行环境，但不记录环境变量；配置和报告不得包含凭据。项目工具链版本、平台和必要服务状态须另行补充。

| 退出码／状态 | 含义 |
|---|---|
| `0`，`passed` | 本轮已配置的自动检查通过；不表示代码审查或整体验收已通过 |
| `0`，`passed_with_warnings` | 必需项通过，但建议项失败／不可执行／超时，仍需按范围报告 |
| `1`，`failed` | 至少一项必需检查失败、不可执行或超时 |
| `2`，`configuration_error` | 配置、路径或证据无法使用；未取得通过结论 |
| `3`，`stale` | 检查期间或核实时输入／配置已变化，旧结果不能覆盖当前状态 |

执行器按命令退出码记录结果，不会解析测试收集数、跳过数或报告内容；仍须核实项目命令确实覆盖预定对象。只运行有界、会退出的命令，避免 watch／后台服务。超时会结束本次命令；POSIX 上同时回收其进程组，其他平台只保证直接进程结束，另核查后代进程是否退出。

## 输入摘要与旧证据核实

目录中的 `.git`、`node_modules`、`.venv`、`__pycache__` 和 Python 字节码不计入摘要；除此之外，执行器不按技术栈自动排除构建输出。选择真实输入，输出尽量放在受验目录外，避免构建生成或改写文件使本轮结果失效；不要为避开失效而漏掉生成输入或实际受验文件。

目录符号链接及经过它的输入路径需改为显式选择真实目录；文件链接解析后也须在项目内。依赖环境、工具版本或外部系统变化仍需主 agent 另行判断并重验，摘要一致不等于这些条件未变。

在交付或现有事件入口中核实结果，无需重跑命令：

```sh
python3 /path/to/coder-assistant/scripts/run_review_checks.py \
  --project /path/to/project \
  --verify /path/to/review-run/result.json
```

核实会重算指定输入的内容与元数据及配置摘要，保留原始报告且不执行检查命令；失效或失败结果不变成通过。当前证据格式为 `schema_version: 2`；不支持的旧格式返回证据错误，须重新运行，不能据此取得通过。它只能核对所声明的输入，不能验证历史 TDD、模型审查、规定的人审或未声明的依赖。

CI 可调用同一执行器，依据退出码决定作业结果并上传日志及 `result.json`；每轮用新目录，按实际提交关联结果。CI 如何接入和阻止完成沿用[主流程](自动检查.md#5-保存证据与接入自动化)，不能仅凭执行器存在就声称自动触发已生效。
