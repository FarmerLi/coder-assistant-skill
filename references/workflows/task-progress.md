# 任务状态与进度

## 权威状态与责任

Issue 保存本项执行状态和证据，任务平台看板展示其实际进度；父项汇总从子项结果派生，不在文档或聊天另建人工维护的实时台账。聊天提供有时间点的摘要，不替代平台事实。代理运行状态、Issue 开关、看板字段、PR 阶段及验收结果分别核实。

采用任务平台时，接收任务读取当前平台成员关系、字段选项及父子依赖，确定状态写入责任方。执行者同步其子项，集成负责人同步父项及整合结果；同一字段同一时刻一个责任方。采用平台执行跟踪且已有任务维护授权时，状态同步属于本轮交付，无须逐次批准；只读评审或无写回授权不更改平台。字段不存在或权限不足时保留具体待同步项并继续无依赖工作，不创建字段、伪造状态或发送额外评论。

## 按事件同步

状态语义由下表定义，具体选项名称由项目配置映射；没有对应选项时使用已有任务的阻塞／说明能力，不擅自新增工作流。

| 事件 | 状态及证据 |
|---|---|
| 尚未纳入执行或范围未明确 | 待规划／待澄清，不能因建单就标进行中 |
| 范围、验收及启动所需依赖具备 | 就绪；依赖可用依据是实际产物，不仅是前置关闭 |
| 实际开始实现／调研 | 进行中；记录责任方与工作区／任务入口 |
| 依赖、权限、环境阻塞或解除 | 同步原因、受影响部分及解除条件；部分阻塞不停止无依赖工作 |
| 本项约定实现、必要验证及提交／PR 完成 | 待评审／待验收；分别记录子项局部、父项全量和远端检查状态 |
| 评审返修或已整合子项暴露缺口 | 受影响项恢复进行中或重开，并关联修复 PR；保留原交付证据 |
| 本项验收与约定交付条件全部满足 | 完成并按[关闭规则](delivery-and-closeout.md#关联issue关闭与现场清理)收尾；子项目标可以是父分支，父项不能由子项关闭自动推定完成 |
| 取消或延期 | 记录有效决定及父目标影响，不能计作通过 |

每次阶段变化及时同步本次受影响字段并回读；可合并同一事件产生的写入，不逐条工具操作刷新，不拖到全部工作结束再批量补记。调用超时先查询实际状态再补写。回读包含 Issue、看板成员关系和负责字段；写入成功但看板未变仍属待同步。平台故障或权限阻塞时记录待同步事件与最后核实状态，继续无依赖工作；不能因状态写回失败阻断整个调度，也不能声称平台已更新。

父项在首个执行项启动后反映进行中，必要子项整合后但全量未验时保持相应待验证状态；只有父目标的完整条件满足才完成。子项已合入父分支但主 PR 未交付时，父项仍保留主线交付待办。

## 用户可见的进度

开始时简述范围、并行分工、关键依赖和本轮交付边界。阶段变化、阻塞、范围决定或验证失败时给出紧凑摘要；持续工作遵守宿主的进度更新频率，等待无变化不反复播报相同结果，也不让长命令遮蔽进展。

多子项摘要保持固定口径：已完成／进行中／待评审／受阻／未启动的数量，当前关键路径，主要阻塞及解除条件，下一完成标志。数量来自已核实状态，同一子项不重复计数；必要时链接具体 Issue。实现、子项整合、父项全量、人工验收及主线交付分开说明。

耗时明显偏离原预期时，说明实际时间花在实现、等待资源、检查、返修还是平台操作，指出已采取的调整和剩余不确定性；没有依据不虚报预计完成时间。沿已有事件、命令起止时间和证据还原，不建立逐条工具调用日志或新监控系统。结束时报告交付结果及未完成门槛，按[等待规则](delivery-and-closeout.md#提交后的等待与评审反馈)退出，不承诺后台监听。

运行资源的并发、保留与停止按[验证资源与执行预算](automated-checks.md#验证资源与执行预算)管理，进度摘要报告资源阻塞及恢复条件。
