# 自动检查与流程接入

自动化执行可确定的检查并返回原始证据，审查者判断需求、设计和真实后果。优先调用项目已有脚本、任务入口和 CI；缺少必需检查时按实际风险补充，不要求先建立通用审查平台。

## 选择命令与触发时点

从仓库指令、脚本、构建配置和既有 CI 查出适用命令、运行条件及副作用。选择与本次验收及影响相关的检查，同时保留项目要求的必需项；命令失败不能静默降为非必需。纯风格交给既有格式／lint 工具，自动格式化应先完成再固定本轮检查输入。

| 时点 | 可自动执行的工作 | 判断边界 |
|---|---|---|
| 实现前 | 相关测试基线 | 原有失败记录来源和影响，不当作新实现的 RED |
| 切片或相关文件变化后 | 受影响测试、类型／边界／格式检查 | 独立命令才并行；共享端口、数据库、缓存或文件时串行或隔离 |
| 独立审查前 | 必需检查集合，保留证据 | 失败先定位，能独立推进的审查仍可进行 |
| 修复后 | 缺陷复现用例及受影响回归 | 聚焦修复，依据影响扩大；不重复整个无变化过程 |
| 交付、提交或已有 PR 更新时 | 核对证据是否仍有效，执行已有 CI 必需项 | 待运行、失败、超时和旧提交结果不能冒充当前成功 |
| 已授权的合并或发布 | 项目要求的合并后检查、冒烟及恢复核对 | 沿用项目实际流程，不从普通编码自动进入发布 |

本地回合并属于[默认交付](回合并.md)，核实最新目标的实际整合候选，并将合并后必需检查关联到目标最终提交。远端 PR 自动合并、推送与发布不因此获得授权。

宿主已有文件事件、任务结束事件或 CI 入口时，可接入同一检查命令。命令式自动检查是否能阻止完成，由宿主／CI 对退出码的处理决定，Markdown 本身没有强制能力。结束事件只核实当前结果，过期时返回失败原因并安排修复／重跑；避免结束事件反复启动新的审查或无限重试。

不同会话的命令在各自专属 worktree 运行，同一会话主 agent 与子 agent 共用会话路径并协调副作用；运行资源按[并发工作区](../shared/并发工作区.md)按需复用、隔离或排队。顺序执行器只协调本次调用，不构成会话内所有命令或跨会话的资源锁。

## 可选的本地执行器

需要批量运行、保存日志或从现有自动化读取结果时，使用[执行器](../../scripts/run_review_checks.py)。小任务已有命令即可，不要求额外配置。执行器只用 Python 标准库，顺序执行以避免默认争抢共享资源；不调用模型、修改验收、安装依赖或创建宿主钩子。

配置参考[订单夹具示例](../../assets/自动检查配置示例.json)，替换成目标项目已有命令。配置仅包含 `inputs` 与 `checks`：

- `inputs`：项目内非空路径数组，包含受审代码、测试、相关规则、配置、依赖锁文件及其他会改变结论的输入。递归记录文件内容摘要、文件与目录的权限及目录存在性，含空目录；文件符号链接还记录链接目标，保留显式选择的链接身份。不要仅列改过的单个实现文件而遗漏接口和测试。执行器不会推断完整依赖，也不会追踪外部服务或环境变化。
- `checks`：非空检查数组。每项的 `id` 是唯一的小写英文标识，`argv` 是参数数组；可设项目内 `cwd`（默认 `.`）、正数 `timeout_seconds`（默认 120）及布尔值 `required`（默认 `true`）。非必需项仅适用于项目允许的建议性检查，失败仍显示警告。

使用实际技能目录和目标项目路径调用，例如：

```sh
python3 /path/to/coder-assistant/scripts/run_review_checks.py \
  --project /path/to/project \
  --config /path/to/project-checks.json \
  --output /path/to/new-review-run
```

`--output` 必须是尚不存在的本轮证据目录；不要覆盖历史结果。项目内输出会从输入摘要排除；为容纳输出新建的父目录不计目录元数据，但其中其他文件仍须追踪。执行器先校验整份配置，再逐项运行，记录参数、工作目录、UTC 时间、退出码、持续时间、合并原始日志、检查前后输入摘要和配置摘要，最终写入 `result.json`，并向标准输出返回同一 JSON。继承运行环境，但不记录环境变量；配置和报告不得包含凭据。

| 退出码／状态 | 含义 |
|---|---|
| `0`，`passed` | 本轮已配置的自动检查通过；不表示代码审查或整体验收已通过 |
| `0`，`passed_with_warnings` | 必需项通过，但建议项失败／不可执行／超时，仍需按范围报告 |
| `1`，`failed` | 至少一项必需检查失败、不可执行或超时 |
| `2`，`configuration_error` | 配置、路径或证据无法使用；未取得通过结论 |
| `3`，`stale` | 检查期间或核实时输入／配置已变化，旧结果不能覆盖当前状态 |

目录中的 `.git`、`node_modules`、`.venv`、`__pycache__` 和 Python 字节码不计入摘要，目录符号链接及经过它的输入路径需改为显式选择真实目录；文件链接解析后也须在项目内。依赖环境、工具版本或外部系统变化仍需主 agent 另行判断并重验。命令按数组直接执行，不做 shell 展开；它们仍有自身权限和副作用，执行器不是权限隔离机制。

只运行有界、会退出的命令，避免 watch／后台服务。超时会结束本次命令；POSIX 上同时回收其进程组，其他平台只保证直接进程结束，转交资源前另核查后代进程。

## 核实旧证据与接入 CI

在交付或现有事件入口中核实结果，无需重跑命令：

```sh
python3 /path/to/coder-assistant/scripts/run_review_checks.py \
  --project /path/to/project \
  --verify /path/to/review-run/result.json
```

核实会重算指定输入的内容与元数据及配置摘要，保留原始报告且不执行检查命令；失效或失败结果不变成通过。当前证据格式为 `schema_version: 2`；不支持的旧格式返回证据错误，须重新运行，不能据此取得通过。它只能核对所声明的输入，不能验证历史 TDD、模型审查、规定的人审或未声明的依赖。

CI 可直接调用同一执行器，用退出码决定该检查作业是否成功，并上传日志和 `result.json`；即使失败也保存工件。每轮用新目录，按实际提交关联结果。优先使用现有上传和检查机制，不默认推送代码、发布评论、放宽必需检查或配置远端 PR 自动合并。宿主事件接入应使用该宿主真实协议及防重入机制，未实际安装或验证时只交付配置说明，不声称自动触发已生效。
