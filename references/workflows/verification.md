# 验证与交接

## 验证范围

先验证当前切片，再按真实依赖与副作用扩展到相关模块、接口、调用方和数据。运行项目要求的必要检查；选择类型、静态检查、构建、架构、契约、集成、回归或渲染等适用项，不默认运行所有工具，也不遗漏项目必需检查。

检查成功后，只有新修改、失败或未解决风险才扩大或重复验证。原有失败与本次引入问题分开处理；证据不足时说明尚无法判断，不能仅因名称无关就排除影响。

## 分层验证与整合

确定性检查按[自动检查](automated-checks.md)复用项目本地／CI 入口，独立判断和缺陷处置按[代码审查](code-review.md)执行。实质行为变更或复杂改动优先由[独立验证子代理](../agents/independent-verification.md)在新的上下文检查；小且低影响的改动或宿主不支持委派时，主 agent 完成相应检查并如实说明独立性限制。委派和修改归属按[子代理协作](../shared/agent-collaboration.md)执行。

自动检查、代码审查、运行验收及项目规定的人审分别关联实际结果，某一面通过不能代替其他必需项。主 agent 核对发现与实际文件，对每项实质问题修复并复验或给出有证据的处置理由；已修改但未复验的项保持待验证。

主 Issue 尚未整体验收时，子项仅验证自身范围及直接受影响契约／回归，跨项与约定全量由主项在稳定整合候选上统一验收；不把全量系统 CI 作为每个子 PR 的开发交付前提。实际 CI 状态和合并门槛按[自动检查](automated-checks.md#3-选择触发时点并执行)另行核对。

独立切片各自通过后，主 agent 按[整合复审触发条件](code-review.md#整合复审触发条件)核对组合结果及证据有效性，不能把各子任务的通过直接相加为整体通过。

按[工作区与输入](../shared/workspace-and-baseline.md)核对受测路径及版本，包括应用实际运行的代码；必需项在实际运行前保持待验证。

按[提交、整合与收尾](delivery-and-closeout.md)执行已确定的交付路径。证据绑定实际整合候选；PR 路径核对当前版本评审、平台检查与规定的人审，本地路径核对 rebase 后候选，均不借用旧提交通过。

## 交付前核对

- **范围：** 从本次开始的工作区基线查看自己的改动及新增文件，逐项对应有效任务、验收或有实际依赖依据的必要支撑；核对没有借父项、引用或回归范围夹带独立目标，迁出要求仍有承接；移除自己的无关扩展，保留他人修改。
- **架构：** 检查实际责任、依赖、数据访问、接口兼容和必要迁移，保留自动检查或具体人工证据。没有报错不等于所有边界都已覆盖。
- **规范：** 核对适用条目没有遗漏，符合性证据对应最终差异；已阅读、已有检查命令或测试通过不等于规范已满足。强制项未验证或不符合时说明受限范围，不能声明完整完成。
- **可评审性：** 核对目标／需求定位、简要实现方式与关键注释是否足以解释改动；采用Issue时，按[执行依据与追溯](../shared/execution-contract.md#执行依据与追溯)关联实现、测试及验收要求，可沿用PR或验证记录，不普遍要求代码内编号。引用须有行为及实现／验证摘要，具体写法遵守项目规范，不能复制业务正文成为另一份权威。
- **复用：** 回查新增逻辑是否重复已有能力，重要新建和抽象是否有理由；按真实语义处理，避免机械合并。
- **验收：** 先核对实际修改是否达成原始目的与目标需求，不能仅凭实现计划完成或测试全绿判定成功；再沿项目测试规范核对验收条目、场景、用例位置与执行结果，区分未覆盖、未验证和有效通过；用例设计／实现状态与本次执行状态分别判断。删除、跳过或隔离后的覆盖缺口与恢复入口仍须保留，局部测试通过不能代替全部范围。
- **接口文档（适用时）：** 按项目规范核对生成／导出入口、实际装配范围、必要内容及契约变更影响；分别报告文档结构与引用检查、页面可读／渲染、真实请求响应一致性和认证回归。启用文档不等于存量契约完整，不能用页面200或生成成功替代业务验证；项目维护工具、访问策略及接口字段要求，技能不复制其规则。
- **证据：** 确认运行针对当前输入及实现状态，记录版本或可定位工作区状态、环境、结果与限制；未执行明确说明。
- **发现处置：** 已确认问题有修复复验或有效处置理由；误报与有意行为有依据，未解决项和影响明确。必要检查没有被降级、忽略或借用其他提交的成功结果。

不要只写“符合架构”“测试通过”“复用完成”。证据可以是已有检查结果和几行定位说明，不要求为每项建立新表格。

## 完成判断

当前任务范围的行为已实现，适用架构与兼容约束满足，必要检查和验收有相应证据，关联Issue依交付约定完成收尾，阻塞与遗留按约定处理，才能报告该范围完成。只完成部分时明确部分范围，不把已写测试、替身通过、任务关闭或代码已提交当成完整交付。

完成范围由已选交付路径决定。默认本轮完成实现、适用验证及约定提交／PR 后等待；分别说明“本轮开发／评审修复完成”和“待人工验收／待合并”，不把 Issue 整体关闭作为进入等待的前提。父 Issue 中仍有可推进的授权子项时，按[依赖调度](../shared/execution-contract.md#父issue执行与依赖调度)继续，不在第一个待评审项处停止。只交补丁或 PR 的任务不虚构合并义务；要求合并与收尾的任务分别报告待验收／待合并、已合并、本地待同步、环境待准备和待清理等状态，不将 worktree 中的通过作为主仓库已完成依据。

任务没有要求部署或业务验收时，不自行增加上线关卡；确有这些要求则分别关联实际结果。不能证明整体完成时，交付已有成果并说明下一步，不夸大也不隐藏。

## 结果与交接

回复以结果为先，简要说明做了什么、为什么如此实现、如何验证、还有哪些限制。重要复用选择与架构检查给出具体位置。无需重复完整执行过程。

需要恢复时依[上下文约定](../shared/project-context.md)更新现有记录，或使用[模板](../../assets/development-handoff-template.md)。包含有效输入、范围、当前改动、最后真实测试、发现处置、未决问题和下一步；保留检查及审查对应的代码状态，不让进度摘要替代需求正文。重复失误按审查方法反馈到回归、确定性规则或适当约定，不默认建立监控或遥测。

需要同步远端时先读取当前内容和关联，按授权保留无关信息；超时或结果不明先查询，避免重复创建。仅关闭任务或更新状态不发送额外评论、消息或通知，除非已有明确授权。
